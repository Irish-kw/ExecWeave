# Граф в реальном времени

ExecWeave может транслировать локальный граф выполнения, пока ИИ-агент или произвольная команда ещё работает.

```bash
execweave live --open -- claude
```

## Текущий контракт

Live-слой runtime намеренно использует кроссплатформенный backend `portable`. В v0.6.4 live-сессия также может принимать второй append-only поток специализированных доказательств через семантический sidecar, отдельный для каждого запуска.

ExecWeave экспортирует путь sidecar в окружение запускаемой команды как:

```text
EXECWEAVE_SEMANTIC_SIDECAR
```

Предварительно настроенные hooks Claude Code, OpenAI Codex, Gemini CLI и Cursor автоматически наследуют эту переменную. Установленный плагин OpenCode делает то же самое. Поэтому их семантические события могут появляться в том же Live Viewer без перехода на отдельную команду `*-record`.

Это **не** означает, что `live` скрытно изменяет настройки провайдера. Интеграцию hook/plugin нужно один раз настроить заранее. Метаданные model-runtime и inference-gateway пока требуют явных emitters, пока для этих интеграций не появится автоматический путь наблюдения.

Linux-backend `strace` сейчас разбирает файлы трассировки после завершения команды. Он предоставляет более сильную атрибуцию на основе системных вызовов, но в текущей реализации не является источником live-событий. ExecWeave не маркирует постобработанные доказательства как live-телеметрию.

Для более сильной Linux-атрибуции после запуска используйте:

```bash
execweave record --backend strace --open -- claude
```

## Поток данных v0.6.4

```text
                         ┌─ hook / plugin провайдера ─→ semantic.jsonl ─┐
команда ─→ portable ─→ events.jsonl ───────────────────────────────────┤
                                                                       ↓
                                                    инкрементальный live-нормализатор
                                                                       ↓
                                                            GraphAccumulator
                                                                       ↓
                                                     localhost HTTP-сервер
                                                                       ↓
                                                        deltas /live.json
                                                                       ↓
                                                          браузер / Top
```

OS runtime-доказательства остаются независимым потоком ground truth. Специализированные доказательства нормализуются в live-граф только предварительно; они не могут переписывать сырой runtime-поток или создавать отсутствующие доказательства.

Браузер и отделённая панель `execweave top` потребляют нумерованные snapshots/deltas из `/live.json`. `/graph.json` остаётся доступным как endpoint текущего snapshot. Инкрементальное чтение обрабатывает только новые добавленные JSONL-байты и буферизует незавершённую последнюю строку до появления перевода строки.

Когда команда завершается, ExecWeave:

1. валидирует завершённый runtime-поток событий;
2. если специализированные доказательства существуют, выполняет каноническое слияние runtime + semantic в `events.semantic.jsonl`;
3. заново строит финальный граф из этого канонического потока, а не доверяет предварительному live-состоянию;
4. записывает `graph.json` и автономный `viewer.html`;
5. помечает live-граф как завершённый и ненадолго обслуживает финальный viewer перед остановкой локального сервера.

Если специализированные события не поступили, финальная материализация остаётся runtime-only.

## Автоматически видимые интеграции Agent

| Интеграция | Автоматическая доставка в Live Viewer v0.6.4 |
| --- | --- |
| Claude Code | **Да**, после настройки hooks ExecWeave |
| OpenAI Codex | **Да**, после настройки hooks ExecWeave |
| Gemini CLI | **Да**, после настройки hooks ExecWeave |
| Cursor | **Да**, после настройки hooks ExecWeave |
| OpenCode | **Да**, после установки плагина ExecWeave |

Все пять интеграций используют один и тот же контракт sidecar на запуск. Регрессионные CI-тесты вызывают каждый адаптер провайдера с общим `EXECWEAVE_SEMANTIC_SIDECAR` и проверяют, что полученные provider-доказательства материализуются в live-граф.

## Terminal Top

`top` больше не рисуется поверх терминала Agent. Исходный терминал остаётся интерактивным для Agent, а панель подключается к той же localhost live-сессии в отдельном окне терминала:

```bash
execweave top -- codex
execweave top --open -- codex
```

`--open` дополнительно открывает браузерный Viewer. Отделённая панель является только attach-клиентом и никогда не запускает второй Agent. Её внутренний attach URL ограничен HTTP на localhost.

## Сетевая доступность

Live-сервер привязывается только к:

```text
127.0.0.1
```

Он не выставляется на `0.0.0.0` и не предназначен для доступа с других хостов локальной сети.

Чтобы явно выбрать порт:

```bash
execweave live --port 8765 --open -- claude
```

Порт `0` используется по умолчанию и просит операционную систему выбрать свободный локальный порт.

## Артефакты

Каталог запуска по умолчанию:

```text
.execweave/runs/<session-id>/
├── events.jsonl
├── semantic.jsonl
├── events.semantic.jsonl      # материализуется только при наличии специализированных доказательств
├── graph.json
└── viewer.html
```

`events.jsonl` остаётся runtime-only. `semantic.jsonl` — сырой специализированный sidecar. Финальный `graph.json` строится из `events.semantic.jsonl`, если специализированные доказательства существуют; иначе непосредственно из `events.jsonl`.

Выбрать другой каталог:

```bash
execweave live --output-dir my-live-run --open -- claude
```

Существующие непустые артефакты отклоняются, а не перезаписываются.

## Предварительная live-нормализация

Во время live-запуска оба JSONL-потока могут быть неполными, поскольку сессия ещё не завершена.

Поэтому live-нормализатор работает инкрементально и консервативно. Уже наблюдаемая runtime-идентичность процесса может использоваться для разрешения специализированных ссылок на процессы, но отсутствующая идентичность никогда не угадывается. Специализированные события, которые ещё нельзя нормализовать, не становятся более сильным доказательством только потому, что были замечены live.

Усечение sidecar сбрасывает предварительную материализацию и повторно проигрывает текущие файлы. Незавершённые последние JSONL-записи буферизуются вместо обработки как завершённых событий. Финальный граф всё равно заново строится из канонического слияния после успешной runtime-валидации.

## Ограничения portable-backend

Текущий live runtime-слой наследует гарантии переносного сборщика:

- обнаружение процессов основано на опросе;
- очень короткоживущие процессы могут быть пропущены;
- изменения файловой системы коррелируются с сессией, а не атрибутируются процессам;
- инспекция сети по процессам зависит от видимости и разрешений операционной системы.

Эти ограничения остаются видимыми в метаданных атрибуции событий. Live Viewer не повышает некаузальное наблюдение до каузального ребра.

## Безопасность больших сессий

Live-обновления используют ограниченную историю deltas вместо повторного чтения всего потока событий при каждом опросе. Если граф превышает безопасный бюджет Viewer, live-endpoint переключается на компактный payload только со счётчиками, чтобы сбор и генерация финального канонического артефакта продолжались без принудительной материализации небезопасного SVG-графа в браузере.

## Будущие нативные live-backend

Планируемые сборщики:

- Linux eBPF;
- Windows ETW;
- macOS Endpoint Security.

Цель — сохранить ту же семантику событий ExecWeave, одновременно улучшая полноту, атрибуцию процессов и накладные расходы времени выполнения.

## Покрытие CI

Конфигурация CI репозитория покрывает:

- запуск localhost live-сессии и генерацию финальных артефактов;
- нумерованные snapshot/delta и resynchronization;
- незавершённые последние JSONL-записи;
- поступление семантического sidecar до готовности runtime-идентичности;
- усечение и повторное проигрывание семантического sidecar;
- каноническую финальную перестройку runtime + semantic;
- автоматическую доставку через общий sidecar для Claude, Codex, Gemini, Cursor и OpenCode;
- отделённое поведение Top без запуска второго Agent;
- ограничение Top attach URL только localhost.
