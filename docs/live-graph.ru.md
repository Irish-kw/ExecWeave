# Граф в реальном времени

ExecWeave может транслировать локальный граф выполнения, пока ИИ-агент или произвольная команда ещё работает.

```bash
execweave live --open -- claude
```

## Текущий контракт

Live MVP намеренно использует сборщик `portable`.

Linux-backend `strace` сейчас разбирает файлы трассировки после завершения команды. Он предоставляет более сильную атрибуцию на основе системных вызовов, но в текущей реализации не является источником событий в реальном времени. ExecWeave не маркирует постобработанные доказательства как live-телеметрию.

Для более сильной Linux-атрибуции после запуска используйте:

```bash
execweave record --backend strace --open -- claude
```

## Поток данных

```text
команда
  ↓
portable collector
  ↓
events.jsonl
  ↓
частичная материализация графа
  ↓
локальный HTTP-сервер
  ↓
/graph.json
  ↓
viewer в браузере
```

Браузер опрашивает `/graph.json`, пока запуск активен. Каждый snapshot строится из тех же контрактов потока событий Фазы 1 и графа Фазы 2, что и финальные артефакты.

Когда команда завершается, ExecWeave:

1. валидирует завершённый поток событий;
2. записывает `graph.json`;
3. записывает автономный `viewer.html`;
4. помечает live-граф как завершённый;
5. ненадолго обслуживает финальный viewer, после чего завершает локальный сервер.

## Сетевая доступность

Live-сервер привязывается только к:

```text
127.0.0.1
```

Он не выставляется на `0.0.0.0` и не предназначен для доступа с других хостов локальной сети.

Чтобы явно выбрать порт:

```bash
execweave live --port 8765 --open -- claude
```

Порт `0` используется по умолчанию и просит операционную систему выбрать свободный локальный порт.

## Артефакты

Каталог запуска по умолчанию:

```text
.execweave/runs/<session-id>/
├── events.jsonl
├── graph.json
└── viewer.html
```

Выбрать другой каталог:

```bash
execweave live --output-dir my-live-run --open -- claude
```

Существующие непустые артефакты отклоняются, а не перезаписываются.

## Неполные snapshots

Во время live-запуска `events.jsonl` намеренно неполон, поскольку сессия ещё не завершена.

Поэтому snapshots live-графа используют режим `allow_incomplete` построителя графа. Структурная валидация всё равно применяется: некорректный JSON, несогласованные сессии, недопустимые сущности или нарушенный порядок последовательности не считаются корректными доказательствами графа.

Финальный граф строится только после успешной обычной валидации полной сессии.

## Ограничения portable-backend

Текущий live MVP наследует гарантии переносного сборщика:

- обнаружение процессов основано на опросе;
- очень короткоживущие процессы могут быть пропущены;
- изменения файловой системы коррелируются с сессией, а не атрибутируются процессам;
- инспекция сети по процессам зависит от видимости и разрешений операционной системы.

Эти ограничения остаются видимыми в метаданных атрибуции событий. Live-viewer не повышает некаузальное наблюдение до каузального ребра.

## Будущие нативные live-backend

Планируемые сборщики:

- Linux eBPF;
- Windows ETW;
- macOS Endpoint Security.

Цель — сохранить ту же семантику событий ExecWeave, одновременно улучшая полноту, атрибуцию процессов и накладные расходы времени выполнения.

## Покрытие CI

Конфигурация CI репозитория включает smoke-путь `live`, который:

- запускает локальную live-сессию;
- выполняет короткую команду;
- записывает финальные артефакты;
- валидирует `events.jsonl`;
- формирует сводку получившегося графа.

Unit-/integration-тесты также напрямую проверяют локальный endpoint `/graph.json`.
