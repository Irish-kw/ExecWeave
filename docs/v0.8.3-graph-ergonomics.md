# ExecWeave v0.8.3 — Graph Ergonomics

This branch targets graph readability and interaction problems observed in dense
multi-agent runs.

## What already exists

`src/execweave/live_view_readability.py` (201 lines) is the current placement and routing
implementation. It is not an undifferentiated grid, and this round must extend it rather
than replace it. What is already there:

| mechanism | where |
|---|---|
| lanes with a rank per node type | `EXECWEAVE_LANES = {runtime:0, root:1, agent:2, model:3, tool:4, endpoint:5, other:5}` |
| a fixed x per lane | `EXECWEAVE_LANE_X = {runtime:0, root:270, agent:540, model:820, tool:1100, endpoint:1380, other:1380}` |
| rank and within-lane order per node | `spec.set(id, {lane, rank, order, x, y})` |
| crossing reduction inside the tool lane | `agentBarycenter`, plus a spawn/send/wait/agent-first sort |
| port-aware routing | `sourcePort` / `targetPort` / `execweavePortY`, ports sorted by target y |
| grouped/bus routing | `bundleByEdge` with `key`, `size`, `groupIndex`; `trunkX` draws the trunk |
| incremental stability across polls | `execweavePlaceStable` keeps prior positions and pushes down on collision |
| a crowding signal | `crowded: edges.length >= 16 \|\| nodes.length >= 12` |
| deterministic tie-breaks | `edgeId(a).localeCompare(edgeId(b))` and `execweaveStableNodeSort` |

**The determinism this round lists as an acceptance criterion is a property the current
code already has, and it comes from those tie-breaks.** Any rewrite that drops them
loses it silently, because a nondeterministic layout still renders.

## Goals

### 1. Adaptive node sizing

`EXECWEAVE_NODE_W = 160` is a constant. Every node is 160px wide regardless of its label,
which is the direct cause of the clipping.

**The constraint that makes this non-trivial:** lane x positions are also constants, and
adjacent lanes are 270–280px apart. A node wider than roughly 270px overlaps the next
lane. Adaptive width therefore cannot be done alone — `EXECWEAVE_LANE_X` has to become
derived from the widest node in each lane rather than a fixed table. Treating goal 1 as a
one-constant change will produce nodes that overlap the lane to their right.

`execweaveCollision` and `execweavePlaceStable` also assume a uniform width and must take
each node's own width once widths vary.

Rules:
- A node's width fits its label up to a ceiling of 320px.
- Beyond the ceiling the label wraps to at most two lines, then ellipsis.
- The full label stays available via `title` and the inspector.
- Lane x is computed from the widest node in each lane, preserving the current minimum
  gap between lanes.

**On `collaborationspawn_agent`:** this is not an ExecWeave defect and must not be
"fixed" by inserting a separator. Both naming paths take the provider's string verbatim —
`codex_adapter._tool_entity` from the hook payload's `tool_name`, and
`codex_rollout_trace_base` from the rollout's `kind`. Nothing in the package joins a
namespace to a name. The string is Codex's own function name for a namespaced tool, so
splitting it for display would show a separator that was never observed. Widen the node;
keep the label.

Acceptance criteria:
- `collaborationspawn_agent`, `collaborationsend_message`, long file paths and network
  endpoints render without overflowing node bounds.
- No node overlaps a node in an adjacent lane, at the widest label in the fixture.
- Enlarged nodes participate in collision resolution rather than being pushed under
  routed edges.

### 2. Reversible focus state

Selecting a node focuses it and its related graph. There is currently no affordance that
returns to the unfocused graph: `syncSelection` clears `selectedNode` only when the DOM
already has nothing selected, and no key or control clears the selection itself.

Rules — all three, not "when practical":
- A `Clear focus` control in the graph controls.
- Clicking empty canvas clears focus.
- Escape clears focus.

Acceptance criteria:
- Focus can be entered and cleared without reloading the page, by each of the three
  routes above.
- Clearing restores the normal graph opacity and visibility state.
- A live poll arriving while focused neither clears focus nor traps a stale focus state.
- The same behaviour holds in live, finished, and standalone `viewer.html`.

### 3. Placement gaps

The pipeline exists. Two things are missing from it.

**Connected components are not separated.** Every node is placed by its type's lane, so a
file or endpoint island with no relationship to the execution spine still occupies a row
in the lane it belongs to and stretches edges that pass it. Components should be packed
separately or moved to secondary lanes.

**`file` has no lane of its own.** It falls through `execweaveLane` to `other`, which
shares rank 5 and x 1380 with `endpoint`. A run with real filesystem activity therefore
piles files and endpoints into one column. v0.8.1 made file nodes canonical by path and
foldable, so this lane is now the crowded one.

Rules:
- Preserve the existing spine ordering: runtime → root → agent → model → tool → evidence.
- Keep `execweavePlaceStable`; incremental repositioning across polls is already correct
  and is a non-goal to change.
- Give disconnected components their own packing, out of the primary routing space.

Acceptance criteria:
- On a fixture with a two-agent spine plus six disconnected file nodes, no edge of the
  spine passes through the region occupied by the disconnected set.
- Node positions for an unchanged payload are byte-identical across two renders.

### 4. Routing consistency

This premise is correct as originally written: there are four distinct routing families in
the code today — a right-angle trunk for bundles, two different bend curves, and an
offset route for backward edges — chosen per edge rather than by one rule.

Rules:
- One primary family for normal execution edges, left-to-right ports.
- Keep bundling; it already reduces clutter and already carries `size`, so multiplicity
  (`×5`) can be rendered from data that exists.
- A distinct style — dashed, or a separate route — only where the semantic difference is
  intentional: backward and lifecycle relations.
- Keep every existing tie-break.

Acceptance criteria:
- On `tests/multi_agent_run_fixture.py` with five agents, the rendered edge-crossing
  count is **lower than the v0.8.1 baseline recorded in the same test**, and the test
  fails if it rises. Record the baseline in the first commit that touches routing;
  "fewer crossings" without a number cannot fail a build.
- Routing is deterministic for the same payload: two renders produce identical path data.

### 5. Folded nodes

v0.8.1 collapses a crowded type into a `viewer:folded:<type>` node carrying
`viewer_folded_members`, with every member edge rewired to it by `canonicalId`. Layout has
to handle these:

- A fold node's label is a count, not a path (`28 earlier files`), so it sizes differently
  from its members.
- A fold node concentrates the edges of everything it holds, so it is the densest node in
  its lane and the strongest case for bundling.
- The fold threshold is `--fold-budget N`, not a constant. Layout must be correct at any
  budget, including one high enough that nothing folds.

Acceptance criteria:
- A run rendered at `--fold-budget 5` and the same run at a budget high enough to fold
  nothing both produce a readable graph with no overlapping nodes.

## Renderer constraint

Live mode, finished runs, and `viewer.html` continue to use the same dashboard renderer
and interaction semantics. This is the v0.7.9 boundary and it is not reopened here.

## Non-goals

- Do not change execution evidence semantics to make the graph prettier.
- Do not discard process/file/network/tool/model evidence.
- Do not introduce layout that makes the graph jump on every live poll;
  `execweavePlaceStable` is the existing answer and stays.
- Do not rewrite `live_view_readability.py` from scratch. The mechanisms in the table
  above are the starting point.
- Do not change release metadata to 0.8.3 until implementation is complete and release
  preparation begins.

## Validation

Focused regressions for:
- computed node bounds at long labels, including no adjacent-lane overlap;
- clear-focus by control, by empty-canvas click, and by Escape;
- deterministic placement and routing for a representative multi-agent graph;
- disconnected evidence not displacing the primary spine;
- edge-crossing count against the recorded baseline;
- fold nodes at two different `--fold-budget` values;
- live polling preserving layout and focus;
- standalone viewer parity.

Every item needs a Chromium behaviour check, not a source assertion: this round changes
what the page looks like, and only the browser can see that.

Run Ruff, pytest, the viewer browser suite, and the platform CI required by the affected
paths before merge.
