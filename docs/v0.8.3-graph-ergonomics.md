# ExecWeave v0.8.3 — Graph Ergonomics

This branch targets graph readability and interaction problems observed in dense multi-agent runs.

## Goals

### 1. Adaptive node sizing

- Node width must expand to fit ordinary labels instead of clipping them prematurely.
- Long labels may wrap to at most two lines before ellipsis is used.
- Full labels remain available via hover/title/inspector.
- Sizing rules may vary by node type when that improves readability.

Acceptance criteria:
- Labels such as `collaborationspawn_agent`, `collaborationsend_message`, long file names, and network endpoints are readable without overflowing node bounds.
- Enlarged nodes participate in layout spacing so they do not overlap neighbors or routed edges.

### 2. Reversible focus state

- Selecting a node may focus/highlight that node and its related graph as today.
- Users must always have an explicit way to return to the unfocused graph.
- Provide `Clear focus` in the graph controls.
- Clicking empty canvas and pressing Escape should also clear focus when practical.
- Live polling and payload refresh must not trap the UI in a stale focus state.

Acceptance criteria:
- Focus can be entered and cleared without reloading the page.
- Clearing restores the normal graph opacity/visibility state.
- The same behavior works in live, finished, and standalone viewer renderers.

### 3. Hierarchy-aware node placement

Use a layered/hierarchical placement pipeline rather than treating all nodes as one undifferentiated grid.

The intended pipeline is:
1. classify/partition graph roles and connected components;
2. assign flow layers/ranks;
3. order nodes within layers to reduce crossings;
4. place nodes with label-aware spacing and compaction;
5. route edges after positions are known.

Guidelines:
- Preserve the main execution spine first: processes/agents -> model/tool -> evidence targets.
- Agent/subagent relationships should remain visually prominent.
- Low-connectivity file/network/process islands must not block or stretch the primary execution flow.
- Disconnected components should be packed separately or moved to secondary lanes instead of occupying critical routing space.
- Live updates should prefer incremental/local repositioning so existing nodes do not jump unnecessarily.

### 4. Consistent edge routing

- Choose one primary routing family for normal execution edges; avoid arbitrary mixtures of large curves and right-angle connectors.
- Prefer left-to-right ports for the normal flow direction.
- Distribute multiple edges across node sides rather than forcing every connector through one center anchor.
- Shared tool/model destinations should support grouped/bus-like routing where this reduces clutter without changing graph semantics.
- Repeated equivalent relations may display multiplicity (for example `x5`) while retaining the underlying evidence.
- Exceptional/backward/lifecycle relations may use dashed styling or a distinct route only when the semantic difference is intentional.

Acceptance criteria:
- Connected nodes are not separated by unrelated islands that force unnecessarily long edges.
- Dense multi-agent graphs show fewer crossings and less edge overlap than v0.8.2 on the same input.
- Routing remains deterministic for the same graph payload.

## Renderer constraint

Live mode, finished runs, and `viewer.html` must continue to use the same dashboard renderer and interaction semantics.

## Non-goals

- Do not change execution evidence semantics merely to make the graph prettier.
- Do not discard process/file/network/tool/model evidence.
- Do not introduce layout behavior that makes the graph substantially jump every live poll.
- Do not change release metadata to 0.8.3 until the implementation is complete and release preparation begins.

## Validation

At minimum, add focused regressions for:
- long node labels and computed node bounds;
- clear-focus behavior;
- deterministic placement/routing for representative multi-agent graphs;
- disconnected/low-connectivity evidence not displacing the primary execution spine;
- live polling preserving layout/focus behavior;
- standalone viewer parity.

Run the normal Ruff, pytest, viewer browser suite, and platform CI required by the affected paths before merge.
