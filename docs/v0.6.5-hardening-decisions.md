# ExecWeave v0.6.5 Hardening Decisions

This document records which recommendations from the post-v0.6.4 hardening review are accepted, modified, deferred, or rejected. It is intentionally narrower than the review itself: recommendations are not treated as requirements unless their claims match ExecWeave's actual evidence model and current implementation.

## Decision principles

1. `Event is ground truth` means raw observations remain canonical, but it does not imply every backend has the same capture fidelity.
2. Severity and evidence fidelity are separate dimensions. A severe behavior can be supported by weak evidence; the report must expose both instead of silently lowering severity.
3. Derived state (graphs, indexes, caches, projections) is never promoted to canonical evidence.
4. Security claims must match the actual trust boundary. A checksum stored beside attacker-writable evidence is not an adversary-resistant trust anchor.
5. v0.6.5 is a hardening release. New Agent/IDE, gateway, model-runtime, language, SSE, Rust, or storage-architecture expansion is frozen unless it fixes a demonstrated correctness or security defect.

## Recommendation decisions

| Spec | Decision | v0.6.5 position |
| --- | --- | --- |
| SPEC-01 Fidelity declaration | **Accept with corrections** | Add an explicit fidelity contract derived from backend/scope/evidence. Never claim byte-level dataflow. Do **not** globally cap finding severity for portable evidence; expose evidence quality separately. |
| SPEC-02 Hash chain + manifest | **Modify before implementation** | A deterministic chain is useful for corruption/post-hoc modification detection, but a manifest in the same writable run directory does not make evidence tamper-evident against a malicious observed process. Implement only after the integrity claim and trust anchor are specified correctly. |
| SPEC-03 Threat model + evasion tests | **Accept — implemented** | Executable regressions cover portable sampling gaps, child lifetime, socket polling, attribution limits, and a strace short-lived-child control. Backend observation limits are documented in [`runtime-threat-model.md`](runtime-threat-model.md) with parity across the existing eight documentation languages. |
| SPEC-04 Rule packs | **Accept later in 0.6.5** | Data-driven rules are useful. Initial untrusted rule packs should use bounded/simple matchers; arbitrary regex should not be part of the first public rule-pack contract. Rules must not be allowed to claim unproven byte/data flow. |
| SPEC-05 Session corpus / real hook fixtures | **Accept** | High-value regression coverage. Fixtures must be sanitized, deterministic, and retain provenance about how they were captured. |
| SPEC-06 Viewer assets + Canvas thresholds | **Partially accept / defer renderer switch** | Asset extraction is maintainability work. Hard-coded SVG→Canvas thresholds are not accepted without benchmark evidence. Existing protective mode already prevents catastrophic rendering and must remain. |
| SPEC-07 SQLite cross-session index | **Accept architecture, defer implementation** | A rebuildable index/cache fits the evidence model, but it is not required before fidelity/evidence contracts are stable. Any future query result must point back to canonical run evidence. |
| SPEC-08 Per-run Live access token | **Accept** | Loopback-only does not isolate users/processes on shared hosts. Add a per-run token and keep it out of written artifacts. Document that this protects the HTTP interface but is not a substitute for OS user/process isolation. |
| SPEC-09 Freeze i18n to EN + zh-TW | **Reject as written** | Do not remove or abandon the existing eight-language documentation. Freeze **new languages** during 0.6.5, while continuing parity for already-supported translations. |
| SPEC-10 Evidence grades | **Accept, design carefully** | This is strategically important, but grade semantics must be orthogonal to severity and must be derived from observable provenance/attribution rather than marketing labels. |

## Explicitly rejected claims

- `portable backend => findings can never be high severity` — rejected. Severity describes the behavior/impact; evidence fidelity describes how strongly ExecWeave observed it.
- `hash chain + local manifest => malicious observed agent cannot tamper with evidence` — rejected unless the terminal trust anchor is outside the attacker's write boundary or cryptographically signed by a protected key.
- `Linux is complete` — rejected as a blanket statement. The Linux strace backend has stronger syscall attribution for supported operations; that is not the same as complete OS-wide visibility or byte-level dataflow.
- `switch to Canvas at exactly N nodes` — rejected until measured. Thresholds must be benchmark-driven.

## v0.6.5 implementation order

1. Fidelity contract and backend/scope limitations.
2. Live HTTP access token and token-leak regression tests.
3. Threat-model/evasion regression tests.
4. Evidence-grade contract.
5. Real/sanitized integration fixtures.
6. Rule-pack contract.
7. Revisit integrity chain with an honest trust-anchor design.

SQLite indexing, renderer replacement, SSE, and Rust remain outside the first v0.6.5 hardening wave unless benchmark or correctness evidence changes the decision.
