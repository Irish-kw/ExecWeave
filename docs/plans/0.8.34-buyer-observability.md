# ExecWeave 0.8.34: user-facing remediation, change impact, and acceptance

Date: 2026-09-18 (Asia/Taipei)  
Baseline: v0.8.33 / `b2bdd9e4e2acf0e035f94f935e167769ca9adcea`  
Working branch: `feature/0.8.34-buyer-observability`  
Status: active development plan, not a completion report.

## 0. User goals and delivery boundaries

A buyer making a substantial investment needs more than an animated graph or a count of captured events. I want a user to investigate a run's content, responsibility, outcome, and evidence gaps without reading source code, searching raw JSON, or asking me where a file is stored.

The product must answer:

1. What was requested, which business roles participated, and what stage has the run reached?
2. What did each agent receive and return, and which model and tool invocations did it use?
3. Which observed inputs, calls, retries, and handoffs explain the result? Hidden reasoning must not be guessed.
4. What did A hand to B? Was B merely the intended recipient, or is delivery or consumption actually evidenced?
5. Where did the task fail? Does an agent's completion claim contradict the test results?
6. Which processes, files, and network endpoints were involved? Is ownership exact or merely correlated?
7. Can another person read the same content and limitations after receiving an export?

"The data is stored somewhere; find it yourself" is not a completed product experience. Green automated tests and a single completeness percentage are not substitutes for user acceptance.

### Development boundaries and invariants

- Make reversible, non-force commits on the working branch. Recheck remote branch and main before writes to avoid overwriting concurrent changes.
- Keep this phase separate from merge, tags, releases, and package-version changes. Do not automatically close external tracking issues.
- Do not alter upstream CAMEL, AutoGen, or MetaGPT task/SOP behavior to make the demonstration look better.
- Do not invent senders, recipients, delivery, consumers, model ownership, hidden reasoning, or missing content.
- Presentation changes must preserve raw events, content hashes, native identities, and observed failure outcomes.
- Keep real user conversations, raw captures, secrets, and original screenshots out of the public repository. De-identify regression data or label it synthetic.
- Do not report unexecuted checks as PASS. Separate synthetic contracts, recorded-run replay, fresh capture, and user journeys.

## 2. Work packages

### W01: separate three classes of status (P0)

Expose independent areas for:

- Execution: `running`, `succeeded`, `failed`, `interrupted`, `collector_failed`, or `unknown`.
- Task verification: `unverified`, `agent_claimed_complete`, `tests_passed`, `tests_failed`, or `missing_deliverable`.
- Observability and delivery: content gaps, attribution gaps, final synchronization, and archive integrity.

Exit code zero, an agent's completion claim, passing tests, and complete evidence are different facts. A successful command that ran zero tests does not verify the task. Missing fields in older data remain unknown, not backfilled PASS. Preserve the original collector error when export also fails.

Acceptance includes both "process succeeded, task unverified, two tool results missing" and "task failed, evidence complete, failure traceable."

### W02: shared content reading across inspectors (P0; first vertical slice)

Messages, model requests/responses, tool inputs/outputs, and artifacts use one reading contract for previews, expansion, search, copying, cancellation, missing files, and integrity results.

Content carries its run, event/occurrence, source, ownership evidence, hash, size, media type, observation time, representation, and completeness. Capture completeness, preview truncation, retrieval status, verification status, and redaction are separate properties.

Security requirements:

- Resolve only registered run-local `content/sha256/<hash>.<json|txt|bin>` references, not arbitrary file URLs, absolute paths, parent traversal, cross-run paths, or remote URLs.
- Reuse Live authentication and directory restrictions. Missing credentials must not expose content; credentials must not leak through external links or shared exports.
- Default to plain text. Do not execute HTML/scripts, load remote images, or navigate automatically.
- Never label unverified bytes as hash-verified. Explain failure or unavailable verification explicitly.
- Read large content on demand with bounded memory/DOM use and cancellation. Do not meet performance targets by silently discarding content.
- Identical hashes may share bytes while preserving separate call and owner identities. Do not share sensitive caches across runs.

First connect one realistic tool-content reference through secure reading, display, error handling, and tests. Offline and cross-provider integration remain required before W02 can be considered complete.

### W03: complete agent work history (P0)

Make the sequence navigable: task, received context, observed output, model exchanges, tools, message handoffs, and deliverables. Task/Response cards are summaries, not the entire history.

- Retain original control tokens but classify them as control events. They must not become the only deliverable, nor automatically make the preceding text a verified final answer.
- Show only source-exposed visible explanations under Thinking. Their absence is not a capture fault; never generate substitute reasoning.
- Paginate, search, and navigate the middle of long histories, including a specified round 83 in a run exceeding 200 rounds.
- Preserve equal text from different occurrences. Historical assistant content repeated in a cumulative request is not a new assistant response.
- Do not fill gaps with root, sibling, or shared-model content. Same-named agents and independent `/root` identities remain isolated.
- New events must not close an older expanded round, change its page or owner, or force scrolling to the bottom.

### W04: investigate individual model/tool invocations (P0)

Each model call shows the requesting agent, model, observed request/response, timing/status, errors, retries, and provenance. A hook's user prompt is not necessarily the full request sent to the model. Usage and costs without reliable evidence remain unknown.

Each tool call exposes arguments, result, errors/exit state, timing, and supported process/file/network relationships. `x25` opens the 25 invocation records. Empty strings, null, unavailable content, disabled capture, missing files, truncation, and redaction must remain distinguishable.

Shared models/tools must not merge different invocations. Unknown owners remain accessible. Aggregation is presentation-only and every occurrence retains a route to its raw evidence.

### W05: message and artifact handoffs (P0)

Keep sent, addressed, delivered, and consumed states distinct and evidence-backed. Expose message bodies and context; do not infer consumers from time proximity or shared files.

Artifacts show the execution-time snapshot, producer, observation time, hash, source event, and evidenced consumers/lineage. Same-named versions remain separate.

Prefer the captured snapshot. A later workspace read must be labeled as the current version, never historical evidence. A path appearing in text does not authorize an automatic file read. State explicitly when missing historical content cannot be reconstructed.

### W06: connect the default workflow and OS evidence (P0 usability; P1 visual polish)

Provide three connected areas: workflow (tasks, roles, message summaries, important artifacts), investigation (searchable timeline), and runtime evidence (processes, files, network, providers, and unattributed records).

- Role lists and search must work without learning canvas pan/zoom first.
- Do not hide important errors and unattributed evidence. Collapsed groups show counts and remain expandable.
- Do not automatically treat `/root` as noise; it may itself be a business role.
- Do not turn every message into a permanent node. Expandable handoff groups should prevent a new message hairball.
- Make relevant OS evidence reachable in one step from an agent/tool, preserving the product's runtime-inspection value.
- Fit applies to the visible scope explicitly chosen by the user. Do not label a cropped view as the whole graph or seize the camera after user interaction.
- Every view-only aggregation preserves original node/edge mappings, counts, selection, and provenance.

### W07: itemized health and cross-provider contracts (P0)

Report readable message bodies X/Y, model requests/responses X/Y, tool inputs/results X/Y, present and verified snapshots X/Y, unknown owner/delivery/consumer counts, final synchronization, and archive status.

Denominators describe explicitly defined, versioned known items, not global recall. Compute end-to-end recall only in experiments with independent ground truth, not by using the recorder's own output as the denominator.

Gap reasons include `not_exposed` (requires source evidence), `capture_disabled`, `unsupported_parser`, `capture_failed`, `missing_blob`, `hash_mismatch`, `preview_only`, `not_verified`, and `unknown`. Do not blame providers for missing local files or unexecuted verification.

Cross-provider parity means consistent reading and limitation explanations, not identical source exposure. Metadata-only capture can be a deliberate choice, not a recorder failure.

### W08: the Live/Finished/Offline delivery chain (P0)

Use the same renderer and content contract. Final synchronization requires a successful authoritative fetch; failure is visible and manually retryable. Stopping polling alone does not prove synchronization.

Verify reference closure: every content reference claimed as included exists, matches its declared size/hash, and accompanies the export. It remains readable on another machine after the original server is shut down. Three top-level files alone are insufficient.

Read older archives without changing their recorded version; missing fields remain unknown. Keep original evidence separate from redacted sharing exports. Redacted derivatives receive new hashes and recorded derivation links; never modify original bytes while retaining the original hash claim.

## 4. Implementation and rollback order

A. Freeze known failures: verify versions, hashes, and missing files; establish failing tests; distinguish real replay from synthetic fixtures.

B. Complete one vertical path: a tool body from reference through safe retrieval, display, errors, Live, and Offline. Extend that reader to models/messages/artifacts rather than building four new filename-only panels.

C. Normalize history and identity: multiple rounds/tasks, shared calls, retries, and equal text. Change a collector only when evidence locates the gap there.

D. Add handoffs, artifacts, search, and workflow presentation. Establish readable content before changing layout so data and visual defects remain independently diagnosable.

E. Validate archive and user journeys: old data, clean installed wheel, three operating systems, real providers, relocated Offline use, and independent operation.

Each batch has an identifiable commit with implemented scope, exclusions, commands/results, and impact. Revert individual batches without force pushes, deleting raw data, or experimenting on main. Prefer additive reader compatibility and explicit feature controls where appropriate; controls must not conceal failures of required gates.

## 5. Verification matrix

### Evidence classes

- **Synthetic contract:** verifies selected data shapes and boundaries, not actual source exposure.
- **Historical replay:** verifies presentation of existing evidence, not a new recorder's capture behavior.
- **Fresh capture:** establishes end-to-end evidence for specified OS, provider, and versions; do not generalize to untested combinations.
- **User-only journey:** investigates without raw files or author guidance; does not replace code-correctness tests.

### Coverage that must remain intact

Windows, Linux, and macOS; Live, the completed original page, reopening while the server remains available, and Offline after shutdown. Preserve the 13 existing provider contracts: Claude, Codex, AGY, Cursor, OpenCode, Ollama, llama.cpp, vLLM, LM Studio, Anthropic, OpenRouter, LiteLLM, and OpenAI-compatible. Include CAMEL, AutoGen, and MetaGPT, native sessions, and metadata-only capture.

Unsupported native combinations or unavailable credentials are BLOCKED/NOT_RUN with reasons, not fresh PASS results inferred from fixtures.

### Required cases

| ID | Scenario | Acceptance |
|---|---|---|
| B01 | Normal process exit without task evidence | Do not claim task success. |
| B02 | Agent claims completion; tests fail or run zero cases | Show the claim beside the observed result. |
| B03 | Inputs/outputs for each role | Read them without leaving the Dashboard. |
| B04 | Terminal control token | Retain it in history; distinguish the deliverable. |
| B05 | Same-named agents and independent roots | No identity or content mixing. |
| B06 | Shared models/tools | Inspect each invocation and evidenced owner. |
| B07 | 200 rounds, long bodies, equal-text turns | Retrieve middle/tail content and retain distinct occurrences. |
| B08 | New events while reading an old round | No forced collapse, page change, scrolling, or camera takeover. |
| B09 | Send without receive evidence | Delivery remains unconfirmed. |
| B10 | Filename-only output and same-named versions | Read snapshots or show their absence, not a current file posing as history. |
| B11 | Missing content or hash mismatch | Explicit error; not verified or complete. |
| B12 | Empty, null, unavailable, disabled, or encrypted content | Distinct states, not one generic "Not observed." |
| B13 | Traversal, file URLs, remote URLs | No arbitrary reads, fetches, or outbound navigation. |
| B14 | Malicious HTML/scripts/remote images | Plain-text display without execution. |
| B15 | Missing token or cross-run access | Reject access and isolate sensitive caches. |
| B16 | Collector and export both fail | Preserve the original error. |
| B17 | Final synchronization fails, then retries | Visible failure and recovery; no false PASS. |
| B18 | Relocated archive after server shutdown | Content claimed as included remains readable. |
| B19 | Older archive | No backfilled success or changed recording version. |
| B20 | Clean installed wheel | Include new modules/resources; source-only success is insufficient. |
| B21 | Large graph and unattributed events | Discover the main workflow and retain evidence/mappings. |
| B22 | Redacted sharing export | Derived hashes, no secrets, unchanged original evidence. |

### Interaction and performance targets (not measurements)

On fixed reference cases: identify task, roles, status, and gaps within 30 seconds; locate a specified answer or call within 60 seconds; reach the referenced body in at most three actions from its panel.

On fixed hardware/browser with 10 agents, 1,000 calls, 10,000 events, and 50 MB of content: usable first paint within 3 seconds; small-content expansion p95 at most 500 ms; large reads remain cancellable without freezing the interface. Never meet these targets by silently dropping evidence.
